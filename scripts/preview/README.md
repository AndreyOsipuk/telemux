# Превью панели и локальная разработка

Превью - вторая копия telemux рядом с прод-мастером: свой юнит `telemux-preview`
(127.0.0.1:8091), своя база `telemux_preview`, без связи с флотом. На нём и на локальной
панели проверяют правки панели на живых данных, не трогая прод.

| Что | Где |
|---|---|
| бинарь, миграции, скрипты | `/opt/telemux-preview/` (700) |
| окружение (база, логин и пароль панели) | `/etc/telemux/preview.env` (600) |
| юниты | `telemux-preview.service`, `telemux-preview-live.timer` (файлы - здесь) |
| порог миграций | `/opt/telemux-preview/base` - номер последней неидемпотентной миграции прода |

Изоляция от флота: `TELEMT_API_URL` превью указывает в никуда, переменных панели 3x-ui,
ACME, файрвола, кластера, heartbeat и SSH к mtg в окружении нет, таблица `nodes` пуста.
Сеть наружу превью ходит только по кнопке «Проверить связь» (TCP/TLS к точкам входа) и
за релизами GitHub (проверка версий). Кнопка «Обновить» на превью машины не обновит:
агенты подключены к прод-мастеру.

## Локальная панель на данных превью

```sh
PREVIEW_SSH=<ssh-алиас машины с превью> scripts/preview/panel-dev.sh
# или из internal/server/web: PREVIEW_SSH=... npm run dev:preview
```

Поднимает SSH-туннель к превью (сам переподключается при обрыве) и dev-сервер Vite на
http://localhost:5173. Правки в `internal/server/web/src` видны сразу, без сборки. Вход -
логин и пароль превью. Правки серверов и машин из локальной панели попадают в базу
превью, а не в прод.

Без превью (свой демон) - `TELEMUX_DEV_BACKEND=http://localhost:8080 npm run dev`.

## Выкладка и данные

```sh
PREVIEW_SSH=<ssh-алиас> scripts/preview/deploy.sh            # панель + бинарь из рабочей копии
PREVIEW_SSH=<ssh-алиас> scripts/preview/deploy.sh --no-web   # без сборки панели
ssh <ssh-алиас> /opt/telemux-preview/snapshot.sh             # свежий снимок прод-базы
```

- `deploy.sh` собирает бинарь из рабочей копии (в том числе незакоммиченное), кладёт
  миграции и скрипты, применяет миграции новее порога (`migrate.sh`) и перезапускает юнит.
  Новые миграции идемпотентны (`IF NOT EXISTS`), повторный прогон безопасен.
- `snapshot.sh` пересоздаёт `telemux_preview` из `pg_dump` прод-базы, чистит `nodes`,
  применяет миграции, ставит адреса релеев из базы бота и, если есть
  `servers-import.json` (экспорт бота), заменяет им серверы. Правки, сделанные в превью,
  при этом пропадают.
- `live-sync.sh` (таймер, раз в минуту) копирует из прода отчёты агентов - подключения,
  нагрузку, применённые ревизии - и историю нагрузки для графиков. Прод только читается.

Когда прод-мастер обновлён до новых миграций, порог (`base`) менять не нужно: миграции
выше порога идемпотентны и на уже обновлённой схеме ничего не меняют.

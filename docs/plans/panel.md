# План: веб-панель telemux по образцу 3x-ui

## Что не так сейчас

Мастер уже собирает подключения, онлайн, нагрузку машин, версии, ошибки журнала и
сертификаты, но панель этого почти не показывает. Понятия «Сервер N» (тип telemt/mtg,
точки входа, домены, лимиты, SYN-лимиты) в telemux нет: оно разложено по трём таблицам
бота (`servers` + `server_endpoints` для telemt, JSON `mtg_nodes.settings` для mtg,
`relay_exits`) и env, и правится руками через SQL.

## Этап A - показать то, что уже собирается (в работе)

- Обзор: машины онлайн/офлайн, подключения и пользователи онлайн, пары, сертификаты,
  компактная таблица машин с нагрузкой и версиями.
- Подключения: сводка по машинам и продуктам, пользователи онлайн, IP, трафик, фильтры.
- Машины: статус, CPU/память/диск/uptime, версии telemt/mtg/агента, онлайн; карточка
  машины - состояние, ресурсы и ревизии, подключения, ошибки журнала, история, сертификаты.
- Пользователи: онлайн и подключения по каждому.
- Сертификаты: домены, сроки, ошибки выпуска.

## Этап B - «Серверы» (аналог «Входов» 3x-ui)

Новая сущность telemux **server** - то, что видит клиент («Сервер N»):

| Поле | Сейчас в боте |
|---|---|
| номер, название, страна, флаг | `servers.name/emoji`, `mtg_nodes.settings.COUNTRY` |
| тип: telemt или mtg | неявно: строка `servers` или `mtg_nodes` |
| релей, выход | `servers.public_ip`, `RELAY_HOST`, `relay_exits` |
| точки входа ee/dd/web: домен, порт, домен маскировки, через релей или напрямую | `server_endpoints`; у mtg - `RELAY_DOMAIN(_EE)`, `RELAY_PORT(_ALT)`, `RELAY_TLS_DOMAIN`, `WEB_DOMAIN` |
| статус: включён / профилактика / тестовый | `is_active`, `is_test`, `relay_only`, `node_retired` |
| лимиты пользователя: подключения, уникальные IP | env `MAX_CONNECTIONS_USER`, `mtg MAX_CONNS` |
| настройки telemt: SYN-лимиты слушателей, таймауты, домены маскировки, max_connections, pending-handshakes | `apps/mtproxy/config/telemt.json`, env `TELEMT_*`, код |
| настройки mtg: throttle, pending-handshakes, таймауты, client-mss, fronting | `mtg_nodes.settings` |

Экран «Серверы»: список 8 серверов (тип, релей, выход, онлайн, статус, ссылки), форма
сервера с вкладками «Основное», «Точки входа», «Лимиты», «Настройки telemt» или
«Настройки mtg», «Опасные». У каждого поля - пометка, как применяется: сразу, перезагрузкой
telemt (без рестарта) или только рестартом (SYN-лимиты, порты слушателей); для опасных
(смена домена маскировки меняет ee-ссылки всех пользователей) - предупреждение.

Конфиги `telemt.config` и `mtg.config` собирает telemux из описания сервера (сейчас их
собирает бот). Бот берёт описание серверов и точки входа для ссылок из telemux
(`GET /api/v1/servers`, `GET /api/v1/endpoints`), а не из своих таблиц.

Переход: одноразовый импорт из базы бота, затем бот читает telemux, таблицы бота остаются
резервом на время перехода; включение по серверу через режим сравнения, как остальные ресурсы.

## Этап C - ноды как в 3x-ui

- Включить/выключить машину без удаления, запрет удалять машину, пока на ней сервер.
- «Проверить связь», графики нагрузки за сутки/неделю.
- Обновить агента и бинари telemt/mtg кнопкой на выбранных машинах (канарейка).
- Тревоги о падении и подъёме машины.

Дальше - стек машины из панели (`docs/plans/machine-stack.md`) и кнопка «Перенести релей».

## Решения от владельца

1. Описание серверов переезжает в telemux, бот читает его оттуда (рекомендация - да:
   единое управление, бот перестаёт быть источником правды о флоте).
2. Конфиги telemt и mtg собирает telemux, а не бот (рекомендация - да, следует из п.1).

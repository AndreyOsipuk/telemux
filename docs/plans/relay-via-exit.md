## 0. Как сейчас и почему ломается

```
сейчас:
  watchdog/аудит (ps2) --SSH/TCP--> pr1, pr2, pr3, pr4      <- до pr2/pr3 с ps2 нет связи
  агент pr1..pr4 --туннель--> мост на выходе --> мастер telemux   <- работает, но мост «слепой»

цель:
  мастер telemux --> выход (его мост видит свой релей) --> релей
  watchdog/аудит --> только мастер telemux
```

- Живой релей становится «мёртвым», если его не видно с ps2.
- Мастер знает, что релей отчитался, но не знает, через чью ноду. Если релей ходит через
  чужую ноду, этого никто не видит.
- Туннели (`targets.relay_code`) разошлись с картой серверов (раздел 8 спеки).

   - telemux - прошлый бинарь (`telemux.bak-*`), миграция совместима назад: колонки

## Этап 5. Топология без дублирования

Цель владельца: у каждого сервера своя зарубежная машина, у каждого релея - свои выходы, без
дублей. Факты по машинам, инвентаризация и раскладка «было -> станет» - в приватной
документации бота (U25). Порядок: по одному серверу, с проверкой ссылок после каждого; после
каждого переноса синхронизировать туннели (`targets.relay_code`) в telemux и данные бота.

# Перезапуск telemux с окном обслуживания

Оператор указывает коды конкретных машин, адрес мастера и путь к
файлу с токеном. В команду передаёт перезапуск и проверку готовности.
Мастер сообщает срок окна через состояние машины. Проверки продолжают
собирать результаты. Watchdog пропускает тревоги по затронутым путям до
закрытия окна или истечения срока.

    оператор → мастер → окна для выбранных целей → watchdog
        ↓
    перезапуск → проверка готовности → закрытие открытых нами окон

Запуск на мастере:

```bash
python3 scripts/maintenance-restart.py \
  --master http://127.0.0.1:8080 --token-file /путь/к/токену \
  --target ps7 --seconds 180 -- \
  bash -ec 'ssh ps7 "sudo systemctl restart telemux-bridge && sudo systemctl is-active --quiet telemux-bridge"'
```

Задавайте `--target` повторно для нескольких машин. Выберите срок от
1 до 900 секунд с запасом на проверку. Для удалённого мастера используйте
HTTPS. Адрес HTTP подходит для loopback, в том числе через SSH-проброс.
Проверка готовности должна проверять нужный путь, а при перезапуске
мастера также его роль и возвращение отчётов. В примере проверяется
только процесс на ноде.

При конфликте команду не запускаем. Если мастер принял только часть
запросов или ответ потерялся, закрываем лишь окна с нашим значением
`expected_maintenance_until`. API проверяет значение под блокировкой
строки. Ошибка команды оставляет окно до указанного срока, чтобы
мониторинг включился самостоятельно. После успешной команды обёртка
снимает окна через тот же механизм. При сбое закрытия остаток окна
истечёт сам. Повторный перезапуск не захватывает чужое окно.

Приёмка: успешный путь, конфликт второй машины, потерянный ответ
после сохранения окна, ошибка проверки и таймаут TTL. Подтвердить, что
при конфликте команда не запускалась и чужое окно не изменилось.

# ADR 0005. Серверы - описание того, что видит клиент

- Статус: принято (этап B1 - справочник и панель)
- Дата: 2026-11-19
- Связано: [план панели](../plans/panel.md) - этап B, [ADR 0003](0003-telemt-config.md) - telemt.config

## Контекст

Клиент видит «Сервер N»: страну, ссылки ee, dd и web. За каждым сервером - движок (telemt
или mtg), релей в РФ (`prN`) и машина за рубежом (`psN`), точки входа (домен, порт, домен
маскировки), лимиты и настройки движка. Сегодня это описание разложено по базе бота
(таблицы `servers` и `server_endpoints` для telemt, JSON `mtg_nodes.settings` для mtg),
env бота и коду, и правится руками через SQL. В telemux есть только машины (`targets`).

## Решение

В telemux появляется сущность **server** со списком **точек входа**. Этап B1 - только
справочник: описание хранится и правится в панели, но ни на что не влияет. Бот продолжает
брать данные из своей базы. Переключение - этапы B2 (конфиги telemt и mtg собирает
telemux из описания сервера, режим сравнения по серверу) и B3 (бот берёт серверы и точки
входа из `GET /api/v1/servers`). Панель честно пишет, что описание пока справочное.

### Схема (миграция 0010)

`servers`:

| Колонка | Тип | Смысл |
|---|---|---|
| `no` | smallint PK, 1-99 | номер «Сервер N» |
| `name`, `emoji` | text, не пусто / может быть пусто | страна для клиента, флаг |
| `country` | text, 2 буквы или пусто | код страны |
| `engine` | text: `telemt` / `mtg` | движок; после создания не меняется |
| `relay_code` | text → `targets(code)`, NULL | релей в РФ (машина вида `relay`) |
| `node_code` | text → `targets(code)`, NULL | машина за рубежом (вида `exit`) |
| `state` | text: `active` / `maintenance` / `test` / `disabled` | `maintenance` - клиент видит «на профилактике» без ссылки; `test` - скрыт от клиентов, синхронизируется; `disabled` - выключен везде |
| `relay_only` | bool | прямые ссылки скрыты, только через релей |
| `node_retired` | bool | машины за рубежом нет, релей и ссылки остаются |
| `tls_domain` | text | основной домен маскировки (ee) |
| `extra_tls_domains` | text[] | дополнительные SNI |
| `user_max_tcp_conns` | int, NULL | лимит подключений пользователя; NULL - общий по умолчанию |
| `user_max_unique_ips` | int, NULL | лимит уникальных IP пользователя; NULL - без лимита |
| `settings` | jsonb, объект строк | настройки движка по каталогу полей |
| `note` | text | заметка |
| `created_at`, `updated_at` | timestamptz | |

`server_endpoints` - одна строка = одна ссылка:

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | bigserial | |
| `server_no` | → `servers(no)` ON DELETE CASCADE | |
| `protocol` | text: `ee` / `dd` / `web` | вид ссылки |
| `host` | text | домен или IP в ссылке |
| `port` | int 1-65535, 443 | для `web` не используется |
| `tls_domain` | text | домен в ee-секрете; для `ee` обязателен |
| `via_relay` | bool, true | через релей или напрямую на машину |
| `label` | text | подпись кнопки; пусто - по виду |
| `sort_order` | int, 100 | порядок |
| `enabled` | bool, true | |
| `note` | text | |

Уникально `(server_no, protocol, host, port)`. Машина, на которую ссылается сервер, не
удаляется (FK `ON DELETE RESTRICT`).

### Каталог полей

Настройки движка (`settings`) - не произвольный JSON: допустимые ключи, их тип, пределы,
значение по умолчанию и **как применяется** описаны в каталоге (`internal/servercfg`) и
отдаются панели (`GET /api/v1/servers/fields`). Неизвестный ключ или значение не того
типа - 400. Способы применения:

- `instant` - бот и ссылки, без касания машин;
- `reload` - перечитывание конфига без рестарта, подключения не рвутся;
- `restart` - рестарт сервиса, подключения рвутся;
- `firewall` - правила iptables на машине.

Пометка `danger` - смена меняет ссылки всех пользователей (домен маскировки, режим
секрета релея) или рвёт подключения; панель спрашивает подтверждение.

### API

Чтение - токен бота или вход в панель. Запись - то же и только на мастере.

- `GET /api/v1/servers?engine=&state=&limit=&offset=` - страница серверов с точками входа
  и живыми цифрами по машинам сервера (подключения, онлайн, статус агента).
- `GET /api/v1/servers/{no}`.
- `GET /api/v1/servers/fields` - каталог полей.
- `POST /api/v1/servers` - создать (201; номер занят - 409).
- `PUT /api/v1/servers/{no}` - заменить целиком вместе с точками входа (одна транзакция).
- `DELETE /api/v1/servers/{no}` - только выключенный (`state=disabled`), иначе 409.
- `PUT /api/v1/servers` - импорт: до 100 серверов, upsert по номеру, одна транзакция;
  ответ `{inserted, updated}`. Тот же формат - в CLI `telemux servers import <file.json>`.

Ошибки ввода - 400 с кодом: `unknown_machine` (нет такой машины или не того вида),
`engine_immutable`, `unknown_setting`, `bad_setting`, `bad_endpoint`, `batch_too_large`.

## Последствия

- Описание флота в одном месте, правится из панели, а не SQL.
- До B2/B3 есть два источника (бот и telemux). Импорт идемпотентен и повторяется перед
  переключением; расхождение видно в режиме сравнения B2.
- Секреты пользователей и SSH-доступы в описание сервера не входят: доступ к машинам - это
  агент telemux.

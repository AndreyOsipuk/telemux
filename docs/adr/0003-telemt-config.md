# ADR 0003. Основной telemt.toml как ресурс telemt.config

- Статус: принято
- Дата: 2026-11-19
- Связано: [ADR 0001](0001-pull-reconcile.md) - ревизии и агент на машине

## Контекст

Бот готовит основной `telemt.toml` каждой машины (`generateMainConfig`: статика, таймауты,
censorship, `announce_ip`, `include` на users.toml) и раньше клал его по SSH при деплое. Машины
под telemux бот по SSH больше не трогает, а ресурса для основного конфига в telemux не было -
правки статики до машин не доходили вовсе.

В `telemt.toml` уже пишут двое:

- агент для ресурса `telemt.users` пересобирает блок `[[web.vhosts.profiles]]` - профиль на
  пользователя, которого нет в `[access.users]`, делает весь конфиг невалидным, поэтому профили
  меняются вместе с users.toml;
- человек на релеях: WEB-режим (nginx по SNI на :443, telemt на 127.0.0.1:8443, на одном релее
  8453), `announce_ip` и `public_addr` после переездов, `mask_port`, свои каталоги в
  `/var/lib/...`. Эталон бота это затирал: однажды он вернул listener на 0.0.0.0:443, где слушает
  nginx, и telemt ушёл в цикл «Address in use».

Нужно доставлять основной конфиг ревизиями так, чтобы три записи не перетирали друг друга.

## Решение

Новый ресурс `telemt.config` - текст основного конфига машины **без WEB-профилей**. Бот
публикует его через `PUT /api/v1/targets/{code}/resources/telemt.config`, ревизии у каждой
машины свои. Агент не кладёт текст как есть, а собирает файл из трёх частей с явными хозяевами:

| Часть | Хозяин | Откуда |
|---|---|---|
| база | бот | ресурс `telemt.config` |
| машинная часть | человек на машине | `/etc/telemt/telemt.local.toml` |
| WEB-профили | ресурс `telemt.users` | users.toml машины |

Что генерируется из базы бота: всё общее, `announce_ip` (адрес ps-ноды или публичный адрес
релея), путь `include`, порт `[server]` по умолчанию, `tls_domain`. Что остаётся за машиной:
WEB-режим целиком, локальный listener и его порт, `mask_port`, каталоги `/var/lib/...`,
`public_addr` - то, чего нет в базе бота и что правится руками при переездах.

Правила слияния (построчные, база сохраняется байт в байт там, где машина её не трогает):

- `[таблица]`: ключ машинной части заменяет одноимённый ключ базы на его месте, новый ключ
  дописывается в конец таблицы, новой таблицы - в конец файла;
- `[[массив]]`: группа машинной части (все элементы с подтаблицами) заменяет группу базы целиком;
- удалять ключи базы машинная часть не умеет - такую правку надо делать в генераторе бота.

Параметры профилей (`secret_mode`, лимиты сессий и потоков) тоже машинные: сборка берёт их из
профилей текущего `telemt.toml`, как и `telemt.users`, иначе первое же применение переписало бы
`ee` на значение по умолчанию у всех пользователей релея.

`telemt.users` по-прежнему трогает только блок профилей. Сборка `база + машинная часть +
профили(users.toml)` и пересборка профилей в уже собранном файле дают один и тот же текст,
поэтому ресурсы сходятся и не перезаписывают файл по кругу. В цикле агента сначала
применяется `telemt.users`, затем `telemt.config` - он берёт профили из только что
записанного users.toml.

Проверки:

- мастер при публикации: текст разбирается, нет `[[web.vhosts.profiles]]`, есть `include` - иначе 400;
- агент до записи: WEB-режим на машине не теряется (иначе отказ с подсказкой перенести его в
  машинную часть), `include` ведёт на users.toml агента, `[server.api]` не выключен (без API
  агенту нечем подтвердить применение), профилей не больше `max_profiles`.

Применение: временный файл со сверкой → бэкап `telemt.toml.telemux-cfg-bak` (свой суффикс,
чтобы не путать с бэкапом профилей) → замена → SIGHUP → `/v1/config/state`: telemt сам проверил
конфиг и принял его. Поля из `process_deferred_paths` telemt применит только рестартом - тогда
рестарт и проверка: API подтвердил конфиг без отложенных полей, юнит активен, `NRestarts` не
вырос за ~8 с (цикл падений между попытками тоже выглядит как active). Рестарт - только после
того, как telemt признал конфиг валидным при перезагрузке: так невалидный файл не может увести
сервис в цикл. Любой сбой - возврат прежнего файла; если процесс уже перезапускался - рестартом.

Попутно исправлен откат `telemt.users`: он возвращал оба файла из бэкапов, включая бэкап
`telemt.toml`, оставшийся от прошлого применения. При смене одного секрета (профили не меняются)
на машину возвращались профили старого списка. Теперь откатываются только файлы этой попытки.

## Перевод машины

1. `telemux target ... --resources telemt.users,telemt.config,...`, бот публикует базу.
2. На машине с ручными правками: `telemux desired --target <код>` на мастере даёт базу,
   `telemux telemt-local --base base.toml` на машине выводит машинную часть в
   `telemt.local.toml`. Предупреждения - правки, которые машинной частью не выразить.
3. Агент с `TELEMUX_AGENT_MAIN_CONFIG=1` в режиме compare: отчёт называет секции, которыми
   собранный конфиг отличается от файла. Пустое расхождение - можно apply.

## Последствия

- Правка `telemt.local.toml` при включённом `telemt.config` применяется сама при плановой сверке
  агента (раз в 5 минут), с теми же проверками и откатом. Неудачная ревизия не повторяется по
  кругу, но если изменились машинная часть или users.toml - та же ревизия пробуется снова.
- Группа массива в машинной части заменяет группу базы целиком. Если машина держит свой
  `[[server.listeners]]` (локальный listener WEB-релея), `announce_ip` внутри него тоже машинный:
  смена адреса в базе бота до такой машины не дойдёт, его правят в `telemt.local.toml`.
- Поддержан один `[[web.vhosts]]`: профили дописываются к последнему vhost, поэтому конфиг с
  несколькими vhost агент не применяет.
- Откат идёт и при остановке агента посреди применения (отдельный контекст на 30 с): файл и
  процесс telemt не расходятся.

- Основной конфиг машин под telemux снова управляется из бота, единым путём с пользователями и mtg.
- Машинные правки живут в отдельном файле и видны явно, эталон их больше не затирает.
- Разбор TOML построчный, без библиотеки: значения проверяет сам telemt (`config_strict`).
  Экзотика (ключи внутри inline-таблиц, подтаблица массива вне группы) машинной частью не
  выражается - её надо делать в генераторе.
- Включение по машине (`TELEMUX_AGENT_MAIN_CONFIG`), по умолчанию выключено: пока машина не
  переведена, агент `telemt.config` не трогает, даже если ресурс назначен.

# ADR 0004. Сертификаты WEB-доменов выпускает мастер (ресурс tls.web)

- Статус: принято
- Дата: 2026-11-19
- Связано: [ADR 0001](0001-pull-reconcile.md) - ревизии и агент на машине,
  [план «стек машины из панели»](../plans/machine-stack.md) - этап 1

## Контекст

На каждом релее nginx держит TLS доменов `webN` (WEB-режим telemt и mtg). Сертификаты
выпускались на самих релеях тремя способами: certbot webroot, certbot dns-cloudflare,
acme.sh dns_cf. Токен Cloudflare лежал на нескольких машинах, включая релеи - наименее
защищённые машины флота. При переезде релея выпуск приходилось поднимать заново.

## Решение

Сертификаты выпускает и продлевает мастер telemux, на релеи они приходят ресурсом
`tls.web` тем же путём, что users.toml и mtg.config.

- **Домены** - `targets.settings.web_domains` релея, строка через запятую. Тип `settings`
  (`map[string]string`, JSONB-объект строк) не расширяется: массив в JSONB сломал бы
  чтение машин во всех местах, где `settings` сканируется в словарь строк. Строка
  проверяется и нормализуется при записи машины (только имена, без звёздочек и IP; регистр,
  пробелы, повторы); мусор, записанный в обход, цикл пропускает с WARN.
- **Выпуск** - ACME DNS-01 через Cloudflare (lego), ключи ECDSA P-256, новый ключ на каждый
  выпуск. Токен Cloudflare - в файле на мастере (`TELEMUX_ACME_CF_TOKEN_FILE`), в окружение
  не кладётся. Аккаунт ACME (ключ и регистрация) - в базе (`acme_account`, свой на каждый
  каталог), поэтому новый мастер после смены продолжает тем же аккаунтом.
- **Цикл** - только на мастере, раз в час: домены включённых релеев, выпуск при отсутствии
  сертификата или если до конца меньше `TELEMUX_ACME_RENEW_BEFORE` (30 дней). Любая попытка
  пишет `last_try_at`; следующая - не раньше чем через 6 часов (лимиты Let's Encrypt, и
  короткоживущий сертификат не перевыпускается каждый час). Неудача - `last_error` и WARN.
  Выпуск - за интерфейсом `acme.Issuer`, тесты подменяют его.
- **Публикация** - каждый проход, каждой машине с назначенным `tls.web`: JSON
  `{"<домен>": {"cert", "key"}}` со всеми её доменами, у которых есть сертификат. Ревизия -
  только при изменении содержимого (ключи JSON упорядочены, хеш стабилен). Извне ресурс
  не публикуется (`PUT .../resources/tls.web` - 400).
- **Агент** (`TELEMUX_AGENT_TLS_WEB=1`) - проверки до записи (имя домена, пара
  сертификат-ключ, сертификат на домен), затем только изменившиеся файлы: временный файл
  со сверкой → бэкап → замена → `nginx -t` → `systemctl reload nginx`; провал - возврат
  прежних файлов. Чужие домены не трогаются и не удаляются. compare - только отчёт.
- **API** - `GET /api/v1/certs`: сроки и ошибки по (релей, домен), без сертификатов и ключей.

## Последствия

- Токен Cloudflare только на мастере; certbot и acme.sh с релеев уходят.
- Закрытые ключи сертификатов хранятся в базе мастера открытым текстом - как и секреты
  пользователей. Наружу они уходят только в бандле своей машины (токен агента) и в памяти
  мостов выходов, которые этот бандл пересылают.
- Снятие `tls.web` с машины не отзывает уже опубликованную ревизию: бандл продолжает её
  содержать (так устроены все ресурсы). Агент без `TELEMUX_AGENT_TLS_WEB` ресурс не трогает.
- Юнит агента пишет в `/etc/nginx/certs` и `/var/log/nginx` (`ReadWritePaths`): `nginx -t`
  открывает журналы на запись.
- Домены, удалённые из `web_domains`, остаются в `tls_certs` и на машинах; чистка - руками.
- DNS-01 требует, чтобы зона домена была в Cloudflare под токеном мастера.

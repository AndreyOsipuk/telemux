# ADR 0006. Конфиги telemt и mtg собирает telemux (этап B2)

- Статус: принято
- Дата: 2026-11-19
- Связано: [ADR 0005](0005-servers.md) - серверы, [ADR 0003](0003-telemt-config.md) - telemt.config

## Контекст

После ADR 0005 описание серверов есть в telemux, но основной `telemt.toml` (ресурс
`telemt.config`) и `config.toml` mtg-multi (ресурс `mtg.config`) по-прежнему собирает бот
и публикует через `PUT /api/v1/targets/{code}/resources/{resource}`. Пока это так, правка
сервера в панели ни на что не влияет.

## Решение

telemux собирает оба конфига из описания сервера и машины. Переключение - по серверу,
через режим сравнения.

### Сборка

- **`telemt.config`** - для машин сервера с движком telemt: релей (`relay_code`) и машина за
  рубежом (`node_code`, если не `node_retired`). Структура - как у бота: секции general,
  server, listeners, timeouts, censorship, access, upstreams. Значения берутся из настроек
  сервера по каталогу (ADR 0005), а где ключа нет - из значения по умолчанию.
  - `announce_ip` - адрес машины, `targets.settings.address`. Если адреса нет, сборка этой
    машины не идёт, в статусе - ошибка.
  - Локальная часть машины (`telemt.local.toml`) по-прежнему накладывается агентом.
- **`mtg.config`** - для машин сервера с движком mtg: секции как у бота. `[secrets]` - из
  пользователей telemux: действующие, плюс прежний секрет до его срока (`_legacy`).
  Ключи по порядку, вывод детерминирован.
- **Эталон.** Сборщики повторяют сборщики бота байт в байт. Тесты сравнивают с эталонами,
  которые получены из кода бота на синтетических входных данных
  (`internal/render/testdata`).

### Режим сравнения и переключение

- У сервера - поле `config_source`: `bot` (по умолчанию) или `telemux` (миграция 0011).
- Цикл на мастере (раз в минуту, а также после правки сервера или пользователей) собирает
  кандидата для каждой машины и ресурса сервера и сравнивает с текущей ревизией.
  - Результат - в `server_render`: машина, ресурс, sha кандидата, sha текущей ревизии,
    совпадение, ошибка, время.
  - `GET /api/v1/servers/{no}/render` - статус по машинам и unified diff. Строки с
    секретами пользователей в diff заменены на `<secret>`.
- `PUT /api/v1/servers/{no}/config-source {"source": "telemux"}` переключает источник.
  - Без `force: true` переключение разрешено только если последнее сравнение по всем
    машинам сервера совпало, иначе 409 `render_mismatch`.
  - Обратно на `bot` - всегда.
- При `config_source=telemux`:
  - telemux сам публикует кандидата (ревизия - только при изменении содержимого).
  - `PUT .../resources/{telemt.config|mtg.config}` от бота для этих машин отвечает 409
    `managed_by_telemux`, и бот считает это пропуском.

## Последствия

- Правка настроек сервера в панели доходит до машин без бота.
- Расхождения сборщиков видны до переключения, откат - одна кнопка.
- Пока бот собирает конфиги серверов на `bot`, сборщики двух систем нужно держать
  одинаковыми; после переключения всех серверов сборку конфигов из бота можно удалить.
